# Math for AI, From Scratch

A visual, intuition-first book on the math behind modern AI (vectors → transformers), published as a website with MkDocs Material and GitHub Pages. Audience: beginners and visual learners who get lost easily. Author: Vaibhav.

## Commands

```bash
.venv/bin/mkdocs serve                    # live preview at http://127.0.0.1:8000
.venv/bin/mkdocs build --strict           # must finish with no warnings
python3 scripts/make_figures.py           # regenerate every plot into docs/figures/ (never hand-edit SVGs)
python3 scripts/check_book.py             # runs every code block, checks images, <details>, stray $
python3 scripts/check_book.py --render    # also parses Mermaid + renders KaTeX (needs node; see the script)
```

The venv was made with `uv` (the system Python has no `ensurepip`): `uv venv .venv && uv pip install --python .venv/bin/python -r requirements.txt`.

To see the result, screenshot pages with headless Chrome (`/usr/bin/google-chrome`) or puppeteer-core, and look at them before calling a change done.

## Layout

- `docs/` has one Markdown file per page. The order and sidebar titles live in `mkdocs.yml` under `nav:`.
  - `index.md` is the start page: the book's question, a table of which chapter answers which piece, a chapter list, a timeline and how to use the book.
  - `00-toolkit.md` … `10-attention.md` are the chapters. `02b-matrix-views.md` is the optional **Chapter 2½** (equations, determinant, rank, eigenvectors, SVD, convolution).
  - `next-steps.md`, `glossary.md`, `acknowledgements.md` and `license.md` follow the chapters.
- `docs/figures/*.svg` are plots generated by `scripts/make_figures.py`. Set `PREVIEW_DIR=/some/dir` to also write PNG previews you can look at.
- `docs/javascripts/katex.js` sets up KaTeX auto-render. `docs/javascripts/contents.js` is the on-demand contents panel: a header button or the `t` key opens it, Esc closes it, and it is built from Material's hidden navigation.
- `docs/stylesheets/extra.css` holds the immersive layout (sidebars hidden on desktop), the reading column, the quiet fold-out style for `<details>`, the contents panel and the footer.
- `.github/workflows/deploy.yml` builds with `mkdocs build --strict` and deploys to Pages. In repo Settings → Pages, the Source must be **GitHub Actions**; don't use the Jekyll or Static HTML templates.
- `.backup/` holds the original single-file book and the edited single-file version. It is git-ignored and is not the source of truth any more.

## The chapter pattern (keep every chapter consistent)

Every chapter follows this structure. Chapter 1 (`01-vectors.md`) is the reference example.

1. **Opening question**: a `> 🧭 **The question.** …` blockquote with a concrete puzzle the chapter will answer. Then an italic `*Where this fits in the book:*` line tying it to the book's spine.
2. **The spine**: the whole book answers *how does a machine learn to finish "The cat sat on the …"?* Mention it at the start and in "Back to the question" where it fits naturally. Chapter 10's closing finishes the sentence ("mat").
3. **Sections as steps**, each ending with a one-line **bridge** that turns what was just learned into the question the next section answers. No section should start "cold".
4. **Picture first, then a small worked example, then about 20 lines of runnable numpy.** Explain *why* before giving a formula: build the formula up from the picture. (The author pushed back hard on a formula that was "just thrown" at the reader, cosine similarity, and the fix was to build it from shadows and unit vectors.)
5. **Pause and predict**: 1 to 3 per chapter, in this exact form:
   ```markdown
   > 🤔 **Pause and predict.** Question?
   >
   > <details markdown="1"><summary>Answer</summary>
   >
   > Answer text.
   >
   > </details>
   ```
6. **History notes are fold-outs** with a teaser summary, never inline blockquotes:
   ```markdown
   <details markdown="1">
   <summary>📜 <b>History:</b> how least squares found a lost dwarf planet</summary>

   Body text.

   </details>
   ```
   `💡` intuition notes stay as normal `> 💡 **Title.** …` blockquotes in the main flow.
7. **`## Back to the question`** before Check yourself: answer the opening puzzle explicitly.
8. **`## Check yourself`** with hidden answers:
   ```markdown
   1. Question?
       <details markdown="1"><summary>Answer</summary>Answer text.</details>
   ```
9. **`## Chapter N in one breath`**: a two-sentence summary.
10. **`**Next:** [Chapter N+1: Title](file.md). …`** after a `---` rule. It ends on a question or cliffhanger that the next chapter's opening question picks up.

Side roads that most readers can skip go in a fold-out or in Chapter 2½, not in the main path.

## Writing and rendering rules

- **British spelling** throughout (optimise, normalise, licence for the noun, colour).
- **Math**: display math uses `$$` on its own lines. Inline math stays in backticks with Unicode (`‖x‖`, `xᵢ`, `Σ`). **Never write a lone `$` in prose**: it switches on inline math in KaTeX and on GitHub (write "1 million US dollars"). Don't write `\|` inside `$$` (GitHub eats it); use `\Vert`. In tables, use `∣` (U+2223) instead of an escaped pipe.
- **Mermaid** is for flow and box diagrams. Never put Mermaid inside a `<details>` (hidden diagrams render at zero size). Quote node labels: `A["text"]`.
- **Plots** go in `scripts/make_figures.py`, using the validated palette defined at the top of that file (BLUE, ORANGE, AQUA, VIOLET …, light surface `#fcfcfb`). Check for overlapping labels in a PNG preview.
- **Markdown inside HTML** needs `markdown="1"` on `<details>`. A numbered list item that continues after an indented `$$` block needs a blank line before the next item, or the items merge.
- **Numbers in the text must match what the code prints.** Compute them; don't estimate. Every code block must run (`check_book.py`).
- **Layout decisions the author made**: no progress bars or progress indicators ("anxiety-causing"), no visible sidebars on desktop, and the contents panel stays on demand. Orientation comes from the opening question, bridges, Next lines, the start-page chapter list and the `t` contents panel.
